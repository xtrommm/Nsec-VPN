## Working controls and ruled-out hypotheses

- Node lists contain database records with recent successful health checks; no production fake-server fallback was found. Offline catalog fallback is cached real data (`ServerCatalogCache.kt`, `VpnRepository.kt`). Endpoint/config/public-key validation and handshake gating are present (`types.ts`, `TunnelConfigBuilder.kt`, `TunnelNegotiation.kt`). Client keys are generated and encrypted on the device; they are not sent to the backend.
- Promo redemption checks availability/dates/total uses/device uniqueness under PostgreSQL locks; encrypted recoverable code storage and unique redemption constraints already exist (`services/promotions.ts`, `services/promoCipher.ts`, `routes/promos.ts`, Prisma migrations). The duration migration retains exact legacy minutes and stores fractional days; do not round old grants.
- Admin authentication re-reads database roles for protected actions; node/config/promo writes and destructive request actions require SUPER_ADMIN. TOTP is enforced when enabled, but enrollment is an operator task (`middleware/auth.ts`, `routes/admin.ts`, `services/totp.ts`).
- Agent commands use execFile argument arrays and validate interface/public-key/address inputs. Leases and wg configuration are persisted; real restart/reboot persistence still needs a live node check (`agent/src/index.ts`). HMAC protocol v2 binds request path/method/body and signs replies.
- Speed tests stay in-app through a separately signed helper UID, bind requests to a captured VPN Network, validate the observed exit IP and fail on network loss. The main app remains excluded for ads. Helper signing/publishing is still a release requirement.
- DNS selections persist and apply on connect/active DNS changes. Custom IPv6 DNS is validated then rejected for the current IPv4-only tunnel with an explicit message. Private DNS/DoH may choose a different resolver while its transport remains inside the VPN for included apps; resolver selection is not proof of leak prevention.
- Troubleshooting Assistant labels unmeasured DNS/MTU/traffic checks as unverified and distinguishes excluded API traffic from tunnel traffic (`TroubleshootScreen.kt`, `TroubleshootingEvidence.kt`). No invented successful leak test was found.
- Backup policies disable cloud/device-transfer of secrets for both APKs. Release cleartext traffic is disabled; HTTPS certificate validation is retained. No evidence justified adding brittle certificate pinning.
- npm lockfile advisory scans: backend, admin and agent each report zero known advisories. This is time-specific and does not prove dependency safety. Gradle/AGP and transitive npm deprecation warnings need upstream compatibility work, not disabled lint or a fabricated clean-build claim.
- A location-only history scan for private-key PEM headers, common GitHub/AWS token formats and committed credential filenames found no matches. Coverage is limited; generic Base64 keys and arbitrary secrets are not ruled out. The chat-compromised node key must remain rotated. No secret values were printed.

## Privacy / operational checks still required

Source code disables backend HTTP access logging and avoids traffic/client-IP persistence; WireGuard necessarily maintains runtime endpoints, handshakes and counters. Database records include installation IDs, public-key/address leases, device metadata, entitlements, request notes, purchases and ad verification. This is data collection even under a no-traffic-logs policy. CloudPanel/NGINX/Cloudflare/VPS/Google logs and retention cannot be verified from this repository. Publish operator identity, contact, retention and deletion process; review provider access logs and Google SDK consent settings.

Included browser WebRTC can disclose local interface candidates independently of a public exit-IP test. Verify public-IP, DNS, IPv6, WebRTC and VPN-drop behavior on the real phone. OS always-on + Block connections without VPN is the durable kill switch; it can block excluded advertising/API traffic. Changing that trade-off requires the owner’s decision.
